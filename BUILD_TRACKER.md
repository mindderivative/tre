## Milestone 6 — Imperative API Completeness

**Status: ✅ Complete — all 4 phases done (2026-09-16).** Not a rendering/input-dispatch capability gap like M4/M5 — this milestone closes real, concrete holes in `engine-py`'s own imperative (`Window.add_rect`-style, not YAML/`engine-spec`) API surface, each confirmed by direct investigation across M4/M5 rather than assumed: `Node` has no `add_child` (only ever built at the `engine-core` level, with **no cycle detection at all** — confirmed by reading `Tree::add_child` directly, `taffy`'s own rejection aside, a Python caller could attach an ancestor as its own descendant and corrupt the tree); `Node.animate()`'s real property list (`node.rs`) is `opacity`/`corner_radius`/`elevation`/`background` only, no `transform`; neither `Window.add_rect` nor `add_canvas` expose `taffy::Position::Absolute`, so every Python-created node is flex-row/block-flowed only, never freely positioned (the concrete blocker M5 Phase 4 hit while trying to write a positioned node-graph example); and `Tree::absolute_position` still doesn't know `PaintProperties.transform` exists (M5's own post-milestone code review), so overlay anchor placement, splitter-drag geometry, and every `Window`/`View` synthetic-point entry point (`.click()`/`.hover()`/`.right_click()`) silently compute the wrong canvas position for a node inside a panned/zoomed `Container`.
